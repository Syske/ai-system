## 7. 本会话踩过的坑（新会话务必知道）

1. **`git add -A` 会误提交他人未提交文件**：本会话就误把**另一会话**的
   `governance/memory/java/coding-memory.md` 带进提交（已 `reset --soft` 拆出）。
   → **只 `git add <明确路径>`**；提交前用 `git show --stat --oneline HEAD` 核对文件清单。
   → 该 memory 文件至今仍是**他人未提交**状态：**不要代提交**（若其内容违反 memory-English 门禁，
   本会话的做法是**译为英文保持合规但不提交**）。
2. **`config/maintenance.yaml` 是块标量**：行首 `- `、ASCII `: ` 都会破坏 YAML
   （本会话犯过两次；第二次被新加的 `config_yaml` 门禁**首次真实拦截**）。改前想清楚缩进。
3. **`checker` 与 `checked` 同名易混**：`checks/menu.py` 等模块里有 `choose` 等被从
   `cli.utils.menu` 绑定的名字，打桩要打**消费者模块**的属性（`tests` 里已有示例）。
4. **"改完必实测"**：本会话至少 8 处改动**看似正确但实际无效或落错位置**（Lombok 状态机落进规则 #17、
   `_linux_path` 替换切坏 docstring、`spec_updater` 的 `return 2` 未传播退出码……）——
   全部都靠**运行/断言**发现。**不要只读代码就宣布完成**。
5. **写 Python 编辑脚本时用 ASCII 引号包中文会语法错误**（本会话犯过多次）→ 用「」或单引号。
6. **heredoc 追加日志务必用 `<<'EOF'`（带引号）**：否则反引号会被 shell 执行、日志被悄悄破坏。
7. **提交信息用 `git commit -F <file>`**：消息含反引号时用 `-m` 会被 shell 吃掉。
