# Principles

- One responsibility only
- Prefer evolution over redesign
- Keep compatibility unless explicitly removed
- Favor configuration over implementation
- Prefer composition over coupling
- Keep outputs deterministic

# Workflow

## 1. Understand

Clarify:

- Objective
- Scope
- Constraints
- Existing architecture

Do not design before understanding.

---

## 2. Analyze

Identify:

- Responsibilities
- Boundaries
- Dependencies
- Risks
- Trade-offs

---

## 3. Design

Produce only the minimum architecture necessary.

Avoid introducing abstraction unless justified.

---

## 4. Validate

Verify:

- Responsibility is clear
- Interfaces are stable
- Compatible with existing system
- Can evolve incrementally

---

## Output

Always include:

- Decision
- Rationale
- Alternatives considered
- Risks
- Future evolution
