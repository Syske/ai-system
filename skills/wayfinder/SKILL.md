# Wayfinder（决策图规划）

处理一个**远超单会话、路线被迷雾覆盖**的大块工作。目标是找到"从当前到目的地"的路径，
而非直接冲向目的地。把路径绘制为 repo 内的一份**共享决策图**，图上每个子工单是一个
**决策工单**——其解决是一项决策，而非一段可执行的构建切片——逐个解决直至路线清晰。

默认**只规划、不做工**：每个工单解决一个决策，当地图清空（没有剩余的待决策项）时即完成，
并把工作交接出去。注意：做事的冲动通常正是"已到地图边缘、该交接"的信号。

## 何时使用

**使用时：**
- 一个构想太大，超过单次会话可以承载的范围
- 路线（destination 之外怎么走）尚不清楚，需先理清
- 用户明确表示要规划一个大块工作 / 大改造 / 大工程

**不要用在：**
- 单会话即可 settle 的已界定功能（用 grilling / prepare / spec）
- 已完成规划的后续执行切片（用 task-splitter）
- 已进入实现（用 develop / bugfix / review）

## 术语

- **目的地（Destination）**：到达该图终点时看起来的样子——规范、决策、或就地完成的变更（如数据结构迁移）。命名目的地是绘图的第一个动作，它决定每个工单的度量基准。
- **决策工单（Decision Ticket）**：内容是一个"待解答的问题"，答案是一次**决策**，不是可执行的构建切片。这是 wayfinder 工单与普通实现工单的根本区别。
- **迷雾（Fog of War）**：能看出有决策/调查将来会来，但此刻无法精确陈述的问题集。判别测试：**能否现在精确陈述这个问题**（不是能否现在解答它）。能→开单；不能→记入 `Not yet specified`（迷雾区），不预切成工单。
- **前沿（Frontier）**：open + 未阻塞（所有 blocking 工单已关）+ 未认领的子工单——已知范围的边缘。
- **认领**：先把工单赋值给自己，再做任何工作；"谁负责"即"谁认领"。open 且未赋值的工单 = 未认领。

## 决策图格式

决策图是 repo 内的一个文件（`.wayfinder/<effort-name>/map.md`），element 从地址
`openspec/changes/<change>/` 之外独立落地，避免与 OpenSpec 规范目录混杂。

**地图是指针，不是仓库**：它列出已做的决策并指向承载细节的工单。一个决策只存在于一处——
它的工单文件——因此地图从不复述决策，只 gist + 链接。

地图正文（低分辨率，一次会话只读一次）：

```markdown
## 目的地（Destination）
<到达终点时看起来的样子，一两行；每次会话先据此定位，再选工单>

## 备注（Notes）
<领域；每次会话应 consult 的 skill（如 grilling）；本努力项的既有偏好>

## 已定决策（Decisions so far）
<!-- 索引：每个已关工单一行；足以判断相关性，再点开链接读细节 -->
- [<已关工单标题>](相对路径) — <答案的一句话要点>

## 未明确（Not yet specified）
<!-- 迷雾区：范围内的未知，尚未能开单；随前沿推进而毕业 -->

## 超出范围（Out of scope）
<!-- 明确排除在本努力目的地之外的工作；关闭，永不毕业回前沿 -->
```

每个工单是 `.wayfinder/<effort-name>/tickets/<ticket-slug>.md`，其正文是一个问题，
大小约为一个会话可承载（约 100K tokens）：

```markdown
## 问题（Question）
<本工单要解决的决策或调查>
```

每个工单带一个类型标签（见下）。**答案不写在正文里**——记录在关闭时的 resolution 段。
创建工单时产生的资产从工单里链接，不粘贴进正文。

## 工单类型（HITL / AFK）

每个工单要么是 **HITL**（人在环，与真人实时协作，真人替自己说话），要么是 **AFK**（agent 独立推进）。

- **Research（调查，AFK）**：读文档、第三方 API、本地资源（知识库）以浮出一个决策所依赖的事实。resolve 为：把发现写入 repo 内的 markdown 文件并从工单链接。用于需要当前工作目录之外知识的情形。
- **Grilling（访谈，HITL）**：默认类型。与真人访谈以收窄决策（调用已有 `grilling` skill 的决策树访谈）。
- **Prototype（原型，HITL）**：做一个廉价、粗略、具体的工件（提纲、初稿、桩、或逻辑代码）来抬高讨论保真度，从工单链接该原型。用于"它该长什么样 / 该如何表现"为核心问题的情形。
- **Task（任务，HITL 或 AFK）**：必须在某个**决策**之前发生的非决策性手动工作（报名一个服务以便评估其 API、开通访问权限、迁移数据以便观察其形状）。这是唯一一种"做事"的类型——它的价值在于解除决策阻塞，而非交付目的地。能独立做就 AFK，否则交给真人一份精确清单。答案记录做了什么 + 后续工单依赖的事实（凭据位置、新 URL、行数等）。

**HITL 纪律**：HITL 工单只能通过与该真人的实时交流解决；agent 永远不代替真人那一侧
回答（一个自问自答的 grilling agent 已违反此纪律）。

## 迷雾 vs 工单

**能否现在精确陈述这个问题**（不是能否现在回答它）：
- 问题已清晰 → 开单（即使被阻塞暂时无法行动）
- 尚不能清晰陈述 → 记入 `Not yet specified`。不要预切迷雾为工单大小的碎片：迷雾比工单更粗，
  一旦前沿到达，一片迷雾可能毕业成多个工单，或零个。

`Not yet specified` 排除：已定的决策、已是 live 的工单、超出范围的工作。

## 超出范围

迷雾只朝目的地方向聚集。目的地固定了范围，范围之外的工作不在迷雾中、也不属于
`Not yet specified`——它进入自己的 `Out of scope` 区：**明确排除在本努力之外**，且永不毕业。
范围（而非清晰度）决定它落在这里。只有当目的地被重画时，它才作为一次**新**努力回归，而非恢复。

把某项标为超范围是一次范围界定动作，不是路线上的一个步骤。若一个已有工单被证明落在目的地之外
——画图时误纳入，或由一次解决暴露——**关闭它**（closed 工单明确离开前沿），在 `Out of scope`
留一行：要点 + 为何超范围，链接该关闭工单。它不进 `Decisions so far`（后者记录实际走过的路线；
范围边界不是路线的一步）。

## 调用

两种模式。无论哪种，**一次会话至多解决一个工单**（research 工单除外）。

### 绘制地图（Chart the map）

用户用一个松散构想调用。

1. **命名目的地**：先通过 grilling 决策树访谈，确定该图"找到的是什么"——规范、决策、或变更。目的地先定，因为它固定范围。
2. **绘制前沿**：再次 grilling，这次**宽度优先**：在整个空间铺开而非深挖单线，浮出开放的决策与当下可迈的第一步。**若此地没有浮出任何迷雾**——路线已清晰、整个旅程单会话即可承载——则不需要地图。停下并询问用户如何继续（应走 prepare / spec）。
3. **创建地图**（`map.md`）：填好目的地与备注，`Decisions so far` 为空，把迷雾草稿进 `Not yet specified`。
4. **创建可现在就开单的工单**：每个工单一个文件；`Task` 类工单可并行；Research 类可开多个（见下）。按 second pass 补写 blocking 关系（需要文件存在才能互相引用）。落位后按前沿与阻塞排序；尚不能明确的一律留在迷雾（`Not yet specified`）。
5. **必要时触发 research**：对需要额外知识的 research 工单，可并行推进、把发现落回工单文件并链接。
6. 停止——绘制地图是单次会话的工作；它自身不解决任何工单。

### 推进地图（Work through the map）

用户带地图（路径）调用。工单可选——不带则由 agent 自行选下一个决策，非用户指定。

1. **加载地图**——低分辨率视图，不逐个读每个工单正文。
2. **选工单**。用户指定则用之；否则按下述顺序取第一个前沿工单。**先认领**：把工单赋值给自己，再做任何工作。
3. **解决它**——按需 zoom：按 `## 备注` 命名的 skill 决定调用什么；拿不准就调 `grilling` 的决策树访谈。
4. **记录解决**：把答案写入工单文件的 resolution 段，**关闭**该工单，并把一行要点 + 链接追加到地图的 `Decisions so far`。
5. **补充新工单**：把答案已使其可明确化的迷雾毕业为新的工单，每片从 `Not yet specified` 移出，使其只存在于新工单。若答案揭示某工单（这一个或另一个）落在目的地之外，标为超范围而非沿路线解决。

用户可并行运行未被阻塞的工单，因此预期其他会话可能正在并发编辑决策图。

## 决策记录分层（追因对齐）

详细决策按三级落盘，追因时**短期看工单、长期看 ADR**：
1. **工单级**：`tickets/<slug>.md` 的 resolution 段——该次决策为何这么做的完整依据，追因主源。
2. **地图级**：`map.md` 的 `Decisions so far`——每行 gist + 链接，供快速浏览全貌与定位。
3. **ADR 级**：仅当同时满足 `rfc/README.md` 三条件（难撤销 / 无上下文会惊讶 / 真实权衡）时，
   晋升为 `rfc/ADR-xxxx-*.md`。地图与工单不重复保存 ADR 内容，只链接。

铁律：地图与工单文件**绝不堆砌重复的详细决策**——决策只在工单/ADR 一处存在，我处只做索引与链接。

## 输出

- 一份落地于 `.wayfinder/<effort-name>/map.md` 的决策图（含目的地 / 备注 / 已定决策 / 未明确 / 超出范围）
- 若干工单文件（`tickets/*.md`，各含问题与类型）
- 一个到此为止清空的路线：路线已清晰、无新工单，交接给后续执行阶段
